VoipEx Android 클라이언트 기술 명세서

1. 프로젝트 개요

프로젝트명: VoipEx Android Client

목적: VoipEx 서버와 연동하여 1:1 음성/영상 통화 기능을 제공하는 Android 애플리케이션

대상 플랫폼: Android 10 (API Level 29) 이상

주요 기능: WebRTC 기반 실시간 음성/영상 통화, Socket.IO 기반 시그널링

2. 기술 스택

  • 개발 언어: Kotlin 1.9.0
  • 최소 SDK: API 29 (Android 10)
  • 타겟 SDK: API 34 (Android 14)
  • 빌드 도구: Gradle 8.2
  • 아키텍처: MVVM (Model-View-ViewModel)
  • 의존성 주입: Hilt 2.48
  • 네트워킹: Retrofit 2.9.0, OkHttp 4.12.0
  • WebRTC: Google WebRTC 1.0.32006
  • Socket.IO: Socket.IO Client 2.1.0
  • 비동기 처리: Coroutines 1.7.3

4. 주요 기능 명세

4.1 사용자 인증

  • 회원가입 (이메일/비밀번호)
  • 로그인/로그아웃
  • 게스트 모드 로그인
  • JWT 토큰 기반 인증
  • 자동 로그인

4.2 연락처 관리

  • 사용자 검색
  • 연락처 추가/삭제
  • 온라인 상태 표시
  • 프로필 조회

4.3 통화 기능

  • 1:1 음성 통화
  • 1:1 영상 통화
  • Direct Call (게스트 모드)
  • 통화 중 음소거
  • 카메라 전환 (전면/후면)
  • 스피커폰 전환

4.4 통화 제어

  • 전화 걸기/받기
  • 통화 거절
  • 통화 종료
  • 부재중 전화 알림
  • 게스트 간 룸 코드 기반 연결

5. API 엔드포인트

5.1 인증 API

POST /api/auth/register - 회원가입
POST /api/auth/login - 로그인
POST /api/auth/guest - 게스트 토큰 발급
POST /api/auth/logout - 로그아웃

5.2 사용자 API

GET /api/users/profile - 프로필 조회
PUT /api/users/profile - 프로필 수정
GET /api/users/search - 사용자 검색

5.3 통화 API

POST /api/calls/initiate - 통화 시작
POST /api/calls/end - 통화 종료
GET /api/calls/history - 통화 기록

6. WebRTC 시그널링 프로토콜

6.1 Socket.IO 이벤트

이벤트명 방향 설명 페이로드
join-room Client → Server 통화방 입장 {roomId: string}
offer Client ↔ Server WebRTC Offer 전송 {targetUserId: string, offer: RTCSessionDescription}
answer Client ↔ Server WebRTC Answer 전송 {targetUserId: string, answer: RTCSessionDescription}
ice-candidate Client ↔ Server ICE Candidate 교환 {targetUserId: string, candidate: RTCIceCandidate}
toggle-audio Client → Server 음소거 상태 변경 {isEnabled: boolean}
toggle-video Client → Server 비디오 상태 변경 {isEnabled: boolean}
user-left Server → Client 상대방 통화 종료 {userId: string}

8. 권한 요구사항

필수 권한

  • CAMERA - 영상 통화를 위한 카메라 접근
  • RECORD_AUDIO - 음성 통화를 위한 마이크 접근
  • INTERNET - 네트워크 통신
  • MODIFY_AUDIO_SETTINGS - 오디오 설정 변경
  • ACCESS_NETWORK_STATE - 네트워크 상태 확인

9. 보안 고려사항

  • 모든 API 통신은 HTTPS를 통해 암호화
  • JWT 토큰은 SharedPreferences의 암호화된 저장소에 보관
  • WebRTC 연결은 SRTP를 통해 미디어 스트림 암호화
  • TURN 서버 인증을 통한 릴레이 서버 보안
  • 사용자 비밀번호는 서버에서 bcrypt로 해시화

10. 게스트 모드 시나리오

게스트 모드 사용 흐름

  1. 게스트 로그인
    • 로그인 화면에서 "Continue as Guest" 버튼 클릭
    • 서버에서 게스트 JWT 토큰 발급 (role: 'guest')
    • 자동 생성된 게스트 ID (예: Guest_a1b2c3d4)
  2. 메인 화면
    • 연락처 목록 대신 게스트 모드 안내 표시
    • Direct Call FAB 버튼 활성화
    • 타이틀바에 "VoipEx - Guest Mode" 표시
  3. Direct Call
    • FAB 버튼 클릭 시 룸 코드 입력 다이얼로그
    • 통화 타입 선택 (음성/영상)
    • 동일한 룸 코드 입력한 사용자와 자동 연결
  4. 통화 연결
    • Socket.IO를 통한 시그널링
    • WebRTC P2P 연결 수립
    • 서버 측 사용자 검증 없이 통화 진행

게스트 모드 특징

  • 회원가입 불필요
  • 통화 기록 저장 안 됨
  • 간단한 룸 코드로 빠른 연결
  • 임시 세션 (앱 종료 시 소멸)
  • 비디오 코덱: VP8/H.264 자동 선택
  • 적응형 비트레이트: 네트워크 상태에 따른 품질 조정
  • 에코 캔슬레이션 및 노이즈 억제 적용
  • 백그라운드 서비스를 통한 통화 유지
  • 배터리 최적화 예외 처리
